# 模型排行榜

排行榜位于 `/rankings`，公开接口为 `GET /api/v1/rankings?period=week`。页面包括模型 Token 趋势、模型排行、厂商份额趋势、厂商排行及排名升降。

这是平台公开渠道的使用量统计，不代表模型质量或全行业市场份额。采用 Sub2API 原生 Vue 和 Go 实现，没有复制参考项目的前端代码。

## 统计口径

- 时间范围：今日、最近 7 天、最近 30 天、最近 365 天。以服务配置时区为准，当前区间截至快照生成时刻。
- 排名和增长比较：向前平移相同天数的对应区间，避免将今天半天的用量与昨天整天相比。
- Token 总量：普通输入 + 输出 + 缓存读取 + 缓存创建，各计一次；不再次叠加缓存时长子桶。
- 模型名称：优先使用用户请求模型，旧记录回退到记录中的模型名称。Claude 末尾的 `-thinking` 变体合并到对应基础模型，例如 `claude-opus-5-5-thinking` 和 `claude-opus-5-5` 计为同一个模型；榜单、趋势、历史比较、厂商模型数和最常用模型使用相同口径。此规则适用于后续 Claude 版本，不修改原始记录、计费或上游请求。
- 厂商：按模型族识别，与服务账号的平台无关。例如 AWS 渠道的 Claude 仍计入 Anthropic。无法从别名识别厂商时使用实际模型；同一别名涉及多个厂商时模型行显示 Mixed，厂商用量仍分别统计。
- 数据范围：仅当前启用、未删除的非专属分组。不会返回用户、密钥、账号、请求内容或费用。
- 年度及比较区间基于可保留的用量记录；清理历史数据后，统计不代表完整历史。图表显示前 8 名，其余归入“其他”，份额分母保留所有公开模型。
- 模型表最多返回前 100 名，活跃模型数、总 Token、厂商排行和趋势图仍保留完整统计。

## 数据库开销

新增独立只读聚合，不修改请求转发或用量写入路径。查询以半开时间范围利用现有索引，在数据库层排除专属分组。

服务端缓存：今日/7 天为 1 分钟，30 天为 5 分钟，365 天为 15 分钟。相同区间的并发访问共享一次计算；不同区间也最多执行一个数据库聚合。查询总预算为 15 秒，失败短暂缓存 5 秒。响应不暴露数据库错误细节。

## 本地预览

连接已运行的本地后端时：

```sh
cd frontend
VITE_DEV_PROXY_TARGET=http://127.0.0.1:8080 VITE_DEV_PORT=3175 pnpm dev
```

访问 `http://127.0.0.1:3175/rankings`。

只预览已生成的匿名快照时，目录中需要 `today.json`、`week.json`、`month.json`、`year.json` 四个接口 `data` 对象。快照不得包含个人信息，不提交生产数据到仓库。

```sh
python3 scripts/preview_rankings.py --snapshots /absolute/path/to/snapshots --port 8175
```

另一个终端启动：

```sh
cd frontend
VITE_DEV_PROXY_TARGET=http://127.0.0.1:8175 VITE_DEV_PORT=3175 pnpm dev
```

该预览 API 只绑定本机，使用固定快照，不连接生产，也不支持账号操作。使用实际后端时由真实用量自动生成排行榜。

也可以直接预览经过构建优化的页面，不启动 Vite：

```sh
cd frontend
pnpm build
cd ..
python3 scripts/preview_rankings.py --snapshots /absolute/path/to/snapshots --static backend/internal/web/dist --port 3175
```

## 发布与回退

本功能不需要数据库迁移或历史回填。保持现有页面和网关逻辑，通过新增路由与导航进入排行榜。生产发布另行按发布流程执行；回退到前一个应用镜像即可，不涉及账单或账号数据回滚。
